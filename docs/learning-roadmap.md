# 学习路线

这个项目采用“先运行，再理解，再重构”的方式。每完成一个功能，都要完成构建、测试和 Git 提交。

## 已完成

### 1. 读懂现有 C++ 项目

- 头文件与源文件的职责
- 命名空间、类、对象和成员函数
- `const`、引用、`auto` 和返回值
- `std::vector<Book>` 的基本使用
- 从 `main` 到业务类的调用流程

### 2. STL 与现代 C++ 基础

- `std::optional` 表示“有值或没有值”
- Lambda 捕获和参数
- `find_if` 查找元素
- `copy_if` 筛选元素
- `remove_if` 与 `erase` 删除元素
- `stable_sort` 创建排序后的副本
- `std::string::find` 和 `std::string::npos`

### 3. 工程工具

- CMake target、include directory 和链接关系
- `library_core` 静态库的模块化构建
- CTest 和 GoogleTest 测试断言
- Visual Studio 调试器和断点
- Git 分支、提交、合并和推送

### 4. 数据结构与复杂度

- `vector` 按 ID 顺序查找的复杂度是 O(n)
- `unordered_map<int, std::size_t>` 平均用 O(1) 定位 `vector` 下标
- `id_index_` 保存“书籍 ID → `books_` 下标”的映射
- 添加新书时增量更新索引；删除后因 `vector` 下标移动而重建索引
- `find_by_id` 只查询，不修改索引
- 用删除中间元素的测试验证索引不变量

### 5. 文件持久化

- `std::ofstream` 写文件
- `std::ifstream` 读文件
- `std::quoted` 保存包含空格的字符串
- 文件不存在和格式错误的处理
- `SaveStatus` 和 `LoadStatus` 表达具体的保存、加载结果
- 拒绝无效图书和重复 ID，保存失败时保护已有文件
- 程序启动加载、退出保存

### 6. 功能扩展与重构

- 按标题、作者、年份查询
- 作者与年份组合查询
- `read_int` 和 `read_line` 输入辅助函数
- 正常路径、失败路径和边界行为测试
- `BookFilter` 组合多个可选条件
- `BookPage` 表达分页结果、总数和是否有下一页
- `LoanResult` 表达借书和还书的具体结果
- 使用独立的 `book_validation` 模块复用数据校验逻辑

### 7. 代码质量工具

- 使用项目级 `.clang-format` 统一缩进、括号和换行
- 格式化前后运行测试，确认风格改动没有改变行为
- 将格式化和构建检查逐步接入 CI

## 当前能力目标

下一阶段不再提供完整代码，而是只给需求和约束。每个练习按以下流程完成：

```text
需求
→ 拆分任务
→ 选择要修改的文件
→ 设计接口
→ 编写第一版实现
→ 构建并阅读错误
→ 添加测试
→ 调试和修正
→ Git 提交
```

目标是从“能解释已有代码”提升到“能独立完成一个小功能”。

## 下一阶段：独立开发练习

### 练习 1：组合筛选

实现按作者和出版年份同时筛选图书。要求返回新的 `vector<Book>`，不修改内部容器，并测试有匹配和无匹配两种情况。

### 练习 2：持久化边界

处理空文件、重复 ID、损坏记录和保存失败。为每种情况设计明确的返回值或错误信息。

### 练习 3：数据结构优化

比较 `vector` 与 `unordered_map` 按 ID 查找的复杂度。记录插入、查找和删除的代价，并说明为什么不能只用一个容器解决所有需求。

### 练习 4：测试框架升级

在理解手写 `expect` 测试后接入 GoogleTest，使用 `TEST`、`EXPECT`、`ASSERT` 和 `gtest_discover_tests`。

### 练习 5：工程化

- 使用 `.clang-format` 统一代码风格
- 使用 clang-tidy 进行静态检查
- 修复迭代器偏移的有符号/无符号转换警告
- 用 GitHub Actions 自动构建和运行测试
- 为 README 增加构建状态和使用说明

练习 1 至 4 已完成。练习 5 的本地格式化、clang-tidy 和 GitHub Actions 已接入，下一步重点是持续维护 CI 和编写独立功能。

## 实习生水平检查表

- 能根据需求找到应该修改的模块
- 能仿照已有接口写出新功能，而不是复制整个文件
- 能为正常情况和失败情况编写测试
- 能区分编译错误、链接错误、运行时错误和测试失败
- 能使用调试器检查变量和调用栈
- 能提交清晰、范围单一的 Git commit
- 遇到陌生库时能查文档并用最小例子验证

达到这些要求，比记住更多语法更重要。
