# 学习路线

这个项目采用“先能运行，再逐步重构”的方式。每完成一阶段，都应保证程序可运行、测试可通过。

## 第 1 阶段：读懂现有代码

目标：理解头文件与源文件、命名空间、类、`const`、引用和 CMake target。

你要做的事：

1. 从 `app/main.cpp` 的 `main()` 开始，画出一次“借书”操作的函数调用顺序。
2. 在纸上解释 `std::vector<Book>` 为什么适合当前的小数据量场景。
3. 运行程序和测试，故意让一个测试失败，再恢复它。

## 第 2 阶段：完成命令行功能

目标：练习分支、循环、函数拆分和输入校验。

你要实现：

1. 在菜单中加入“删除图书”。
2. 在菜单中加入“按标题搜索”。
3. 在菜单中加入“按出版年份排序后显示”。
4. 用户输入字母时不退出程序，而是清理输入并重新显示菜单。

每项功能都先在 `tests/library_service_test.cpp` 中增加测试。

## 第 3 阶段：数据结构与复杂度

目标：比较顺序表和哈希表。

当前按 id 查找使用 `vector`，时间复杂度是 O(n)。把项目改为同时使用：

- `std::vector<Book>`：保持展示顺序。
- `std::unordered_map<int, std::size_t>`：通过 id 快速定位。

记录添加、删除、查找操作的复杂度变化，并处理删除元素后下标变化的问题。

## 第 4 阶段：文件持久化

目标：学习文件流、错误处理和模块边界。

新增 `BookRepository`，让程序退出后图书仍能保存。先使用简单文本格式，之后再考虑 JSON。业务类不应直接操作 `std::fstream`。

## 第 5 阶段：工程化

目标：接触真实项目的质量工具。

- 使用 `clang-format` 统一格式。
- 使用 `clang-tidy` 做静态检查。
- 使用 Git 分支提交每个小功能。
- 接入 GitHub Actions，自动构建和测试。
- 数据量变大后再使用 Catch2 或 GoogleTest，不急着在第一天引入依赖。

## 第一个练习

请先完成第 2 阶段的“删除图书菜单”。`LibraryService::remove_book()` 已经实现，你只需要：

1. 修改菜单文字。
2. 接收用户输入的 id。
3. 调用 `remove_book()`。
4. 根据返回值输出成功或失败。
5. 在测试中补充“删除存在的书”和“删除不存在的书”两个断言。
